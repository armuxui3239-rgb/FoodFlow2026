# คู่มือหมุนคีย์ (Key Rotation Guide) — v4 ข้อ 11

> **เหตุผล:** คีย์ชุดนี้เคยถูกส่งผ่านช่องทางแชท 2 ครั้ง — ตามมาตรฐาน v4 ข้อ 11 ถือว่า "หมดอายุ" ต้องหมุน
> ผู้ทำ: **คุณ (ที่ dashboard/เว็บเท่านั้น)** — ผมอัปเดต `.env` และตรวจระบบให้หลังคุณหมุนเสร็จ
> ทำเป็นขั้น ๆ หมุนทีละตัว แล้วทดสอบทันทีหลังแต่ละตัว ระบบไม่ล่มระหว่างทาง

## 1) รหัสผ่านฐานข้อมูล (Supabase)

1. Supabase Dashboard → โปรเจกต์ → **Settings → Database → Reset database password**
2. สร้างรหัสใหม่ที่แข็งแรง — อย่าส่งผ่านแชท; วิธีที่ปลอดภัย: วางลงไฟล์ชั่วคราว `TEST-ACCOUNTS.local.md` (ไม่ commit) แล้วบอกผมว่า "ใส่ DATABASE_URL ใหม่แล้ว" — ผมจะอัปเดต `.env` จากไฟล์นั้นและลบทิ้ง
3. ผมจะรัน `bash scripts/qa-all.sh` ยืนยันระบบเดินครบ

## 2) Service role key (Supabase)

1. Dashboard → **Settings → API → API Keys** → กด **Rotate** ที่ service_role key (หรือระบบใหม่: สร้าง `sb_secret_...` ใหม่)
2. คีย์เก่าจะใช้ได้ช่วงสั้น ๆ (grace period) แล้วตาย — อัปเดต `.env` ตามวิธีในข้อ 1
3. ผมรัน qa-all ยืนยัน (ต้องผ่าน 99/99 เหมือนเดิม)

## 3) GitHub Personal Access Token

1. GitHub → **Settings → Developer settings → Personal access tokens** → ลบ token เดิม (`ghp_UWLE...`)
2. สร้างใหม่ **scope เฉพาะ `repo`** (ไม่ต้อง admin:org/delete_repo — ลดระดับความเสียหายถ้าหลุด)
3. แจ้งผมด้วยวิธีไฟล์ชั่วคราวแบบข้อ 1 — ผมอัปเดตการใช้งาน push และทดสอบ push จริง

## 4) SESSION_SECRET (ของระบบเราเอง)

1. ผมสร้างค่าใหม่ 96-hex ด้วย generator เข้ารหัสลับและอัปเดต `.env` (ไม่มีความเสียหาย — แค่ผู้ใช้ถูกล็อกออกครั้งเดียวหลัง deploy ใหม่)

## 5) หลังหมุนครบ — เกณฑ์ปิดงาน

- [ ] qa-all.sh ผ่าน 99/99 ด้วยคีย์ชุดใหม่
- [ ] gitleaks (CI) ยังผ่าน
- [ ] คีย์เก่าทดสอบแล้ว "ใช้ไม่ได้" จริง (ลองเรียกด้วยคีย์เก่า → 401)
- [ ] คีย์ใหม่ไม่เคยผ่านแชทอีกครั้ง
